# Each view is a Tab definition over one engine, and its detail is a strip of Detail tabs

The Review queue, Tracked and Mine used to be three hand-written copies of the same machinery: list rendering, selection, keyboard navigation, filter chips, sorting, dismiss, tab-bar counts and detail rendering in the browser, three copies of the page markup, and per-view load, resolve, summarize and detail in the query layer, the assistant tools and the CLI. Each view is now one declaration: a `VIEWS` entry in `app.js` (rows, haystack, chip groups, named sorts, marks, counts, row and detail HTML, a few optional hooks) driven by one engine, and one `tab.Tab` record in Python (`load`, `resolve`, `summarize`, `detail`) behind hand-written assistant tools and `query` commands whose names and output did not change. A fourth view takes one `VIEWS` entry, one key in `render()`'s data, one `tab.Tab` record, and a listener route only if it dismisses.

The detail pane is a strip of Detail tabs: queue Overview (Status, Reviewers, Description, First-pass review) · Discussion · Diff, Tracked and Mine Overview · Discussion. Counts sit in the labels, panes draw on first open, keys 1 to 4 switch, each view remembers its last Detail tab, and the "awaiting your reply" chip lives in the header and steps through the waiting threads. Every selection writes a per-view deep link (`#pr=`, `#tracked=`, `#mine=` with a stable Branch set id), and `#pr=` links shared before keep working.

## Considered Options

- **Keep three copies and share helpers piecemeal.** No big change, but every behaviour change kept landing three times and drifting (Mine selected by a different id, the queue had its own navigation).
- **One engine with per-view declarations (chosen).** The spike set a bar of 450 source lines out. The honest result was about -340 after unpacking code agents had compressed to hit the number, then -350 with the follow-ups. The bar was accepted as missed because the estimate assumed the row and detail renderers would shrink, and they stayed view-specific. Kept for the single place each behaviour now lives.
- **Detail layouts: linear with folds, a sticky section rail, or tabs.** Compared on real PRs in a throwaway prototype. Tabs won because a long Discussion no longer buries the Diff or the status. Ctrl-F no longer finds text in a hidden Detail tab, which was accepted since the list search finds PRs.
